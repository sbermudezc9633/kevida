Copiar Planillas SOI 2.0 — Persistencia de la planilla copiada

Documento de referencia para replicar el flujo en NSOI 3.0.

Hallazgo principal: el copiado de planillas NO usa el procedimiento almacenado PCK_ALMACENAMIENTO_ARCHIVOS.guardarPlanillaArchivo ni las tablas TMP_*.

Esa cadena es exclusiva del archivo plano. La copia persiste directamente en las tablas definitivas (SOI_PLANILLA, SOI_PLANILLA_APTE, SOI_PLANILLA_CZTE, SOI_PLANILLA_CZTE_NV, SOI_PLANILLA_CZTE_SS, SOI_PLANILLA_CZTE_PF, SOI_PLANILLA_TOTAL_*) mediante DAOs JDBC, dentro de una única conexión.

1.2 ¿Una sola transacción? ¿Rollback por cotizante?

  • PlanillaRegistroBean.guardarPlanillaAportante abre una ConnectionFactory.getConnection() y la pasa al manager; toda la planilla (encabezado + aportante + totales + todos los cotizantes) corre sobre la misma conexión JDBC.
  • No hay commit/rollback explícito en managers ni DAOs: cada PreparedStatement.executeUpdate() se ejecuta con la semántica del Connection del pool (sin demarcación manual — comportamiento consistente con autocommit / commit implícito por statement). La conexión solo se cierra en el finally del EJB.
  • Si un cotizante falla (SQLException → SystemException), la excepción aborta guardarPlanilla y sale del action: en CopiarPlanillasPaso2Action el catch (ApplicationException) externo corta el proceso completo (accion="success", manejarExcepcion). No continúa con los siguientes cotizantes ni con las demás planillas seleccionadas (el único catch interno del bucle es IndexOutOfBoundsException).
  • Consecuencia: ante un fallo a mitad, pueden quedar filas parciales insertadas (la copia no es atómica de forma garantizada). No existe un flag tipo GUARDADA_COMPLETAMENTE que se actualice al final del guardado en este flujo (ese flag lo maneja el procedimiento del archivo plano).

2.2 Firma: fun_soi_secu_planilla

Fuente: database/paquetes/pck_soi_secuencia_planillas.prc (líneas 32, 100). 
function fun_soi_secu_planilla (in_operador varchar2) return varchar2;
  • Parámetro: in_operador = CODIGO_OPERADOR_PILA (VARCHAR2), p. ej. '80' para operador electrónico.
  • Lógica:
    1. SELECT lpad(n.codigo_numeracion,2,0) de SOI_NUMERACION_OPERADOR + SOI_OPERADOR vigentes.
    2. Lee SOI_VALOR_PARAMETRO id_soi_parametro = 432 (nueva_secuencia).
    3. EXECUTE IMMEDIATE 'select lpad(SEQ_SOI_OPERADOR_<operador>.nextval, 8 o 7, ''0'') from dual' — una secuencia por operador (SEQ_SOI_OPERADOR_80, etc.).
    4. Formato del número:
      • Si parámetro 432 = 1: codigo_numeracion(1 dígito si <10, 2 si >=10) || secuencia(8 dígitos).
      • Si 432 ≠ 1: codigo_numeracion || secuencia(7 dígitos) || digito_chequeo_mod11.
    5. Para operador '80' verifica unicidad contra SOI_PLANILLA.NUMERO_ELECTRONICA (MODALIDAD=0) y SOI_PLANILLA_UNIFICADA (bucle hasta encontrar número libre).
  • Retorna: VARCHAR2 (~9–10 chars), que se guarda en SOI_PLANILLA.NUMERO_ELECTRONICA (modalidad electrónica, que es la que fuerza guardarPlanillaAportante vía PlanillaConstantes.MODALIDAD_PLANILLA_ELECTRONICA).

2.4 Resolución de administradoras

  • Copia: resolución en Java. PlanillaCotizanteDTO llega de planillaConsultaMngr.consultarCotizantesDePlanilla ya con idAdm*/codAdm*. En AlmacenamientoPlanillaHelper.insertarCotizante se reconstruyen nit/codigo vía consultarAdministradorVO(id) / consultarTodasAdministradorasVO(id) (ConfiguracionPlanillaConsultaCoherence.consultarAdministradora). No hay token ID|CODIGO en este flujo.
  • Archivo plano: PCK_ALMACENAMIENTO_ARCHIVOS hace inicializarAdministradoras() (caché PL/SQL indexada por COD_ADMINISTRADORA desde SOI_ADMINISTRADORA) y consultarAdministradora(cod) resuelve ID_SOI_ADMINISTRADORA/NIT. La serialización ID|CODIGO sí aparece en parsers de archivo (resolucionAdministradora en arc.biz), no en la copia.

3. Tablas de estacionamiento (TMP) — no aplican a la copia

  • La copia inserta directamente en las definitivas; nunca toca TMP_PLANILLA, TMP_PLANILLA_APTE, TMP_PLANILLA_CZTE ni TMP_PLANILLA_TOTAL_*.
  • Para referencia (flujo archivo plano):
    • TMP_PLANILLA_CZTE: arc.biz/dao/OracleTmpPlanillaCztePRC.java, PK ID_TMP_PLANILLA_CZTE = SEQ_TMP_PLANILLA_CZTE.NEXTVAL, REGISTRADO=0, ID_SOI_PLANILLA = id de TMP_PLANILLA.
    • Columnas GENERAR_AS_ADMINISTRADORA, MORA_*, DISTRIBUCION_EMPLD/EMPLDR existen en TMP_PLANILLA_TOTAL_* y son copiadas tal cual por PRC_ALM_ENCABEZADO_Y_TOTALES a SOI_PLANILLA_TOTAL_*.
    • NOVEDADES (AlmacenarCotizanteTmp.marshallNovedades, arc.biz/r1747/util/AlmacenarCotizanteTmp.java:539): cadena posicional separada por |, 18 posiciones en este orden fijo (vacía si no aplica): 
      ING|RET|TDE|TAE|TDP|TAP|VSP|VST|SLN|IGE|LMA|VAC|AVP|VCT|IRP|COR|COM|

  • guardarPlanillaAportante retorna InformacionPlanillaDTO con idSoiPlanilla (PK nueva), numeroPlanilla (NUMERO_ELECTRONICA), cantidadCotizantes, valorTotal, valorMora. Paso2 lo usa para numeroPlanillaElectronica del DTO de salida y para registrarRevalidacionActivos.

5.3 ¿Se recalculan totales/mora/IBC?

  • Totales y mora: TotalizadorPlanillaMngr recalcula (recalcularMora=true por defecto, solo false para tipo Z) sobre los aportes copiados → VlrGranTotal, VlrGranTotalMora, fechaPagoOportuno. No se copian los totales de la base.
  • IBC/aportes: se copian del cotizante base, excepto: si tiene novedad de retiro de pensión → aporte PENSIÓN en null; si hay ausentismo y ARP/CCF con tarifa=0 y aporte=0 → recalculoIBCActualizacionCotizante + validarActualizarTarifaArp/CCF (recalcula tarifa y valor); novedad VSP → salario = nuevoSalario; idTipoSalario → obtenerTipoSalarioPorDefecto; marcasEdicionDiasDesdeBD recalculadas para seguridad social.
  • Novedades: mapaNovedades se limpia en la copia (ver §4.4).

5.4 Estado, usuario e IP de la copia

  • En Paso2: formaElaboracionPlanilla=COPIADA_POR_PE, copiaPlanilla=true, idSoiPlanillaCopia=idBase, estados/ids/números a null, y si la base estaba PENDIENTE_PAGO_OTROS_CANALES (o restricción cta. bancaria) → estadoPlanilla=GUARDADA; restriccionCtaBc=false.
  • crearplanillaVO: persiste PENDIENTE_PAGO_OTROS_CANALES solo si el DTO aún lo trae; en la práctica la copia queda GUARDADA.
  • usuarioCreacion/ipCreacion = usuario autenticado del request (Paso2 líneas 201-202).

Fragmento PL/SQL relevante (guardarPlanillaArchivo, body línea 2315)

PROCEDURE guardarPlanillaArchivo ( idTmpPlanilla       IN  TMP_PLANILLA.ID_TMP_PLANILLA%TYPE,
                                   idPlanillaGuardada  IN  SOI_PLANILLA.ID_SOI_PLANILLA%type,
                                   modificarPlanilla   IN  NUMBER,
                                   usuario_creacion    IN  VARCHAR2,
                                   ip_creacion         IN  VARCHAR2,
                                   idNuevaPlanilla     OUT SOI_PLANILLA.ID_SOI_PLANILLA%type) is
BEGIN
    idNuevaPlanilla := -1;
    select count(1) into existeIdTmpPlanilla from tmp_planilla where id_tmp_planilla = idTmpPlanilla;
    if (existeIdTmpPlanilla < 1) then return; end if;

    select count(1) into numero_cotizantes from TMP_PLANILLA_CZTE where ID_SOI_PLANILLA = idTmpPlanilla;

    PRC_ALM_ENCABEZADO_Y_TOTALES ( idTmpPlanilla, idPlanillaGuardada, modificarPlanilla,
                                   usuario_creacion, ip_creacion, idNuevaPlanilla);

    PRC_INSERTAR_PLA_COT(idTmpPlanilla, idNuevaPlanilla, usuario_creacion, ip_creacion);

    UPDATE SOI_PLANILLA SET GUARDADA_COMPLETAMENTE = 1 WHERE ID_SOI_PLANILLA = idNuevaPlanilla;

    BEGIN
        PRC_VALIDACION_PLANILLA(idNuevaPlanilla);
    EXCEPTION WHEN OTHERS THEN
        IF SQLCODE = -20005 THEN
            UPDATE SOI_PLANILLA SET VIGENTE = 0, GUARDADA_COMPLETAMENTE = 1,
                   usuario_modificacion='diferencia_totales', fecha_modificacion = SYSDATE
             WHERE ID_SOI_PLANILLA = idNuevaPlanilla;
            COMMIT;
        END IF;
        raise_application_error(SQLCODE, SQLERRM);
    END;
END guardarPlanillaArchivo;

PRC_INSERTAR_PLA_COT (línea 1951): caché de administradoras, marca id_soi_planilla=-1 a cotizantes previos, cursor all_czte (o all_czte_n para tipo N=7 ordenado por id_grupo_cotizante, correccion_mn), por fila: SEQ_SOI_PLANILLA_CZTE → construirCzteVO → insertCzte/insertCzteNv/insertCzteSs/insertCztePf con commits intermedios por bloques.

7. Checklist de fidelidad para NSOI 3.0

  1. La copia persiste solo por JDBC en definitivas; no reutilizar el SP de archivo plano ni las TMP.
  2. Número de planilla nuevo por PCK_SOI_SECUENCIA_PLANILLAS.fun_soi_secu_planilla(codOperador); modalidad forzada a electrónica → NUMERO_ELECTRONICA.
  3. ID_SOI_PNLLA_COPIA = id base; FORMA_ELABORACION = COPIADA_POR_PE; ID_ESTADO = GUARDADA; VIGENTE = 1.
  4. Orden de inserts: SOI_PLANILLA → SOI_PLANILLA_APTE → totales (PCK_ALM_TOTALES.almacenar) → por cotizante CZTE → CZTE_NV → CZTE_SS → CZTE_PF → prc_validacion_planilla (salvo tipo N).
  5. Totales/mora recalculados (TotalizadorPlanillaMngr), no copiados; excepciones IBC/ARP/CCF/VSP salario/novedades limpiadas documentadas en §5.3.
  6. USUARIO_CREACION/IP_CREACION = usuario e IP del request actual.
  7. Fallo en un cotizante → se aborta toda la planilla y el lote completo de copias.
  8. Revalidación posterior: prc_marca_revalidacion_activos si administradoras inválidas o reglas (cot. 21/51/43, 34-12, act. económica ARL, EP714) lo exigen.
